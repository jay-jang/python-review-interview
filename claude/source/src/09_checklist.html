PART 9

레벨별 리뷰 체크리스트

인터뷰 직전에 훑어보는 한 장 요약. 코드를 받으면 위에서부터 차례로 질문을 던져 보세요.

Junior 체크리스트 — 정확성과 기본 관용구

정확성

  • ☐ 빈 입력, None, 0, 음수, 중복, 매우 큰 입력에서 동작하는가?
  • ☐ 0으로 나누기, 인덱스 범위, KeyError 가능성
  • ☐ 모든 분기가 값을 반환하는가? (암묵적 None)
  • ☐ if/if/else vs if/elif/else 혼동
  • ☐ off-by-one: range, 슬라이스 끝 인덱스
  • ☐ 순회 중 컬렉션 수정
  • ☐ 입력 인자를 몰래 변경하는가?

함정

  • ☐ 가변 기본 인자 / 가변 클래스 변수
  • ☐ is vs ==, == None, == True
  • ☐ x == a or b 류의 불리언 실수
  • ☐ 루프 안 람다의 늦은 바인딩
  • ☐ float 금액, round 오해

리소스·예외

  • ☐ open은 with + encoding
  • ☐ bare except, except: pass
  • ☐ print 대신 logging
  • ☐ 네트워크 호출 timeout

가독성

  • ☐ range(len(x)) → enumerate/zip
  • ☐ 수동 합계/카운트 → sum, Counter, 컴프리헨션
  • ☐ 내장 이름 섀도잉 (list, id, type)
  • ☐ 매직 넘버/문자열 → 상수, Enum
  • ☐ 이름이 의도를 드러내는가? 함수가 한 가지 일만 하는가?
  • ☐ 깊은 중첩 → early return
  • ☐ 주석 처리된 코드, 디버그 출력 잔존

Intermediate 체크리스트 — 설계와 유지보수성

설계

  • ☐ I/O와 비즈니스 로직이 분리되어 있는가?
  • ☐ 의존성(DB, 시계, HTTP)을 주입받아 테스트 가능한가?
  • ☐ 반환 타입이 일관적인가? (값 / None / 예외)
  • ☐ bool 플래그 인자, 긴 인자 목록 → 키워드 전용, 데이터 객체
  • ☐ dict 남용 → dataclass/TypedDict
  • ☐ 상속보다 조합, 불필요한 클래스(메서드 하나짜리)
  • ☐ 중복 로직(DRY), 하지만 섣부른 추상화도 경계

예외·로깅

  • ☐ 도메인 예외 계층, raise ... from
  • ☐ 예외를 잡은 곳에서 의미 있는 처리를 하는가?
  • ☐ log.exception, 모듈 로거, 지연 포맷, PII 마스킹

타입·데이터

  • ☐ 공개 API 타입 힌트, Any 남용, 인자는 추상 타입
  • ☐ Optional 값의 None 처리 누락
  • ☐ 시간대 aware datetime, Decimal

성능·메모리

  • ☐ 루프 내 리스트 멤버십, pop(0), 반복 문자열 결합
  • ☐ 대용량 데이터 → 제너레이터/스트리밍
  • ☐ N+1 쿼리, 루프 내 불변 계산
  • ☐ lru_cache 위치·크기·가변 반환값

테스트

  • ☐ 실패 경로/경계값 테스트, parametrize
  • ☐ mock patch 위치, autospec, 과도한 mock
  • ☐ 시간/난수/환경 의존성 고정

Expert 체크리스트 — 동시성, 보안, 운영, 진화

동시성

  • ☐ 공유 가변 상태 + read-modify-write → 락/원자적 연산/설계 변경
  • ☐ async 함수 안의 블로킹 호출, await 누락
  • ☐ 태스크 참조 유실, 예외 유실, 취소 처리, 동시성 제한
  • ☐ DB 트랜잭션 경계, 동시 갱신(낙관적 락, SELECT ... FOR UPDATE)
  • ☐ 재시도 대상이 멱등한가? 백오프+지터
  • ☐ 프로세스/스레드/free-threading 환경에서 전역 캐시 동작

객체 모델

  • ☐ __eq__/__hash__ 계약, 가변 객체 해시
  • ☐ NotImplemented 반환, super() 협력
  • ☐ 메타클래스/디스크립터가 정말 필요한가?
  • ☐ 데코레이터: wraps, async 지원, 타입 보존

보안

  • ☐ SQL/셸/경로/템플릿 인젝션
  • ☐ pickle, yaml.load, eval에 외부 데이터
  • ☐ 비밀정보 하드코딩·로그 노출, secrets/hmac.compare_digest
  • ☐ TLS 검증, SSRF, 리소스 고갈(크기·시간 제한)

운영·진화

  • ☐ 관측성: 구조화 로그, 메트릭, 트레이싱, 요청 ID
  • ☐ 타임아웃·재시도·서킷브레이커, 우아한 종료
  • ☐ 공개 API 하위 호환성, deprecation 경로
  • ☐ 의존성 고정, 라이선스, 지원 Python 버전
  • ☐ 원자적 파일 쓰기 (임시 파일 + os.replace)
  • ☐ 측정 기반 성능 개선 여부, 복잡도 증가 대비 이득
  • ☐ 이 버그가 재발하지 않게 할 장치 (타입, 린트 규칙, 테스트)

자주 나오는 개념 질문 (1)

Q. 리스트와 튜플의 차이는? 언제 튜플을 쓰나요?

리스트는 가변, 튜플은 불변(내용물이 hashable이면 튜플도 hashable → dict 키/set 원소 가능). 관례적으로 리스트는 같은 종류 원소의 가변 길이 모음, 튜플은 위치마다 의미가 있는 고정 구조(레코드). 튜플은 약간 더 작고 상수 폴딩 등 최적화 대상. 의미 있는 필드명이 필요하면 NamedTuple/dataclass.

Q. GIL이란? 그럼 Python에서 멀티스레드는 무의미한가요?

CPython 인터프리터가 한 번에 한 스레드만 바이트코드를 실행하도록 하는 전역 락. 참조 카운팅을 단순하고 빠르게 유지하기 위한 설계. I/O 대기·C 확장(NumPy, hashlib 등)은 GIL을 풀므로 I/O 바운드 작업엔 스레드가 유효하고, CPU 바운드 순수 Python엔 멀티프로세싱이 필요. 3.13에서 free-threaded 빌드(실험적), 3.14에서 공식 지원 단계로 진입했지만 기본 빌드는 여전히 GIL이 있음. GIL이 있어도 += 같은 복합 연산은 원자적이지 않아 락이 필요.

Q. 이터레이터와 제너레이터의 차이는?

이터레이터는 __iter__와 __next__를 구현한 모든 객체(프로토콜). 제너레이터는 yield를 쓰는 함수(또는 제너레이터 식)로 이터레이터를 쉽게 만드는 방법이며, 실행 상태(프레임)를 보존하고 send/throw/close를 추가로 지원. 둘 다 한 번만 소비 가능.

Q. @staticmethod와 @classmethod의 차이는?

classmethod는 첫 인자로 클래스(cls)를 받아 서브클래스에서 호출 시 서브클래스가 전달됨 → 대체 생성자(from_json)에 적합. staticmethod는 아무것도 바인딩하지 않는 네임스페이스 함수. 모듈 함수로 충분하면 그쪽이 더 단순.

Q. __new__와 __init__의 차이는?

__new__는 인스턴스를 생성하는 정적 메서드(클래스를 받아 새 객체 반환), __init__은 생성된 인스턴스를 초기화(반환값 None). 불변 타입(int, str, tuple) 서브클래싱, 싱글톤, 인스턴스 캐싱에서 __new__를 오버라이드. __new__가 다른 클래스의 인스턴스를 반환하면 __init__은 호출되지 않음.

자주 나오는 개념 질문 (2)

Q. 얕은 복사와 깊은 복사의 차이, deepcopy의 비용은?

얕은 복사는 컨테이너만 새로 만들고 원소는 같은 객체를 참조. 깊은 복사는 재귀적으로 복사하며 memo dict로 순환 참조를 처리. 큰 객체 그래프에서 느리고, 파일·소켓·락처럼 복사 불가능한 객체에서 실패. 불변 데이터 구조를 쓰면 복사 자체가 필요 없어짐.

Q. *args, **kwargs, /, *의 의미는?

def f(a, b, /, c, *, d, **kw): a, b는 위치 전용, c는 위치/키워드 모두, d는 키워드 전용, *args는 나머지 위치 인자 튜플, **kwargs는 나머지 키워드 인자 dict. 위치 전용은 인자 이름을 API에서 숨겨 이름 변경 자유를 주고, 키워드 전용은 호출부 가독성과 인자 순서 변경 자유를 줌.

Q. 데코레이터는 어떻게 동작하나요? functools.wraps는 왜 필요하죠?

@deco는 func = deco(func)의 문법 설탕이며 정의(import) 시점에 실행. 래퍼 함수가 원본을 대체하므로 __name__, __doc__, __module__, __qualname__, __wrapped__가 사라짐 → 디버깅, 로깅, 문서화, inspect.signature, pytest/Flask 같은 이름 기반 프레임워크가 깨짐. wraps가 이를 복사.

Q. Python의 메모리 관리 방식은?

CPython: 참조 카운팅(카운트가 0이 되면 즉시 해제) + 순환 참조를 위한 세대별(3.14부터 증분) 가비지 컬렉터. 작은 객체는 pymalloc 아레나에서 할당. 해제된 메모리가 OS로 바로 반환되지 않을 수 있어 RSS가 줄지 않는 현상이 있음. 약한 참조(weakref)로 캐시·옵저버의 순환/누수 방지.

Q. asyncio와 스레드의 차이, async를 언제 쓰나요?

asyncio는 단일 스레드 이벤트 루프에서 협력적 멀티태스킹(await 지점에서만 전환), 스레드는 OS에 의한 선점형 전환. async는 수천 개의 동시 I/O 연결(웹 서버, 크롤러, 웹소켓)에 효율적이지만 모든 I/O 라이브러리가 async여야 하고 블로킹 호출 하나가 전체를 멈춤. 기존 동기 코드베이스에 소수의 병렬 I/O라면 스레드 풀이 단순.

Q. ==와 is, __eq__와 __hash__의 관계는?

is는 동일 객체(id) 비교, ==는 __eq__로 값 비교. __eq__를 정의하면 __hash__가 자동으로 None이 되어 unhashable. 동등한 객체는 해시가 같아야 하며, 해시에 쓰이는 필드는 불변이어야 함.
