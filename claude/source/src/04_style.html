PEP 20 — The Zen of Python (리뷰 근거로 쓰기)

import this로 볼 수 있는 19개 격언 중 리뷰에서 자주 인용하는 것들:

  • Explicit is better than implicit. — 숨은 전역 상태, 마법 같은 메타프로그래밍, from x import * 지적
  • Simple is better than complex. — 과도한 추상화, 불필요한 클래스
  • Flat is better than nested. — 깊은 중첩 → early return(가드 절)
  • Readability counts. — 한 줄 트릭보다 읽히는 코드
  • Errors should never pass silently. Unless explicitly silenced. — except: pass
  • In the face of ambiguity, refuse the temptation to guess. — 애매한 입력은 추측 말고 에러
  • There should be one — and preferably only one — obvious way to do it.
  • If the implementation is hard to explain, it's a bad idea.
def process(order): if order: if order.paid: if order.items: for item in order.items: ship(item) else: raise ValueError("empty") def process(order: Order | None) -> None: if order is None or not order.paid: return if not order.items: raise ValueError("empty order") for item in order.items: ship(item)

PEP 8 — 레이아웃, 공백, import

  • 들여쓰기: 스페이스 4칸, 탭과 혼용 금지
  • 줄 길이: PEP 8 79자(docstring/주석 72), 팀 합의로 99까지 허용. Black/Ruff 기본 88
  • 빈 줄: 최상위 정의 사이 2줄, 메서드 사이 1줄
  • 줄바꿈: 백슬래시보다 괄호 안 암시적 연결. 이항 연산자 앞에서 줄바꿈(수학 표기 방식)
  • import: 파일 상단, 한 줄에 하나, 그룹 순서 ① 표준 라이브러리 ② 서드파티 ③ 로컬, 그룹 사이 빈 줄. 와일드카드 import 금지. 절대 import 권장
  • 공백: 괄호 안쪽 공백 X, 쉼표 뒤 O, 키워드 인자 = 주변 X (단, 타입 힌트가 있는 기본값은 x: int = 0)
  • 비교: is None, isinstance(x, T) (type(x) == T X), if not seq:
  • 후행 쉼표: 여러 줄 컬렉션에 붙이면 diff가 깔끔 (magic trailing comma)

def fetch_orders(user_id: int, *, since: date | None = None) -> list[Order]: """Return orders placed by a user, newest first. Args: user_id: ID of the user. since: If given, only orders on or after this date. Returns: Orders sorted by ``created_at`` descending. Empty if none. 타입 힌트 스타일 (PEP 484 / 585 / 604 / 695)

from typing import List, Dict, Optional, Union, Any def f(xs: List[int], m: Dict[str, Any]) -> Optional[Union[int, str]]: ... def g(items: list = None): # 암시적 Optional, 원소 타입 없음 ... from collections.abc import Iterable, Mapping, Sequence def f(xs: Sequence[int], m: Mapping[str, object]) -> int | str | None: ... def g(items: Iterable[str] | None = None) -> list[str]: ... type UserId = int # 3.12 타입 별칭 def first[T](xs: Sequence[T]) -> T: # 3.12 제네릭 문법 return xs[0]
  • 인자는 넓게, 반환은 구체적으로 (Postel 원칙): 받을 때 Iterable/Sequence/Mapping, 돌려줄 때 list/dict.
  • Any는 타입 검사 포기. 정말 아무거나면 object가 더 안전 (메서드 호출 시 검사됨).
  • Optional[X]는 "생략 가능"이 아니라 "None 가능"이라는 뜻.
  • 공개 API는 반드시 힌트. 내부 지역 변수는 추론에 맡김.
  • from __future__ import annotations: 힌트를 문자열로 지연 평가 (3.14에선 PEP 649로 기본 지연 평가).
  • cast()/# type: ignore가 많으면 설계 문제의 신호. ignore에는 에러 코드 명시: # type: ignore[attr-defined].
  • 타입 힌트는 런타임에 강제되지 않는다 → 외부 입력은 별도 검증.

Google Python Style Guide 핵심 (PEP 8 외 추가 규칙)

Imports

패키지/모듈 단위로 import (from sound.effects import echo 후 echo.f()). 함수/클래스 개별 import는 typing 등 예외적으로.

Exceptions

내장 예외를 의미에 맞게 사용, assert로 인자 검증 금지(-O에서 제거됨), catch-all 금지, try 블록 최소화.

Mutable Global State

지양. 필요하면 모듈 내부(_name)로 두고 접근 함수 제공.

Comprehensions

간단한 경우만. 여러 for 절이나 복잡한 필터는 금지.

Default Arguments

가변 객체를 기본값으로 쓰지 말 것.

Lambda

한 줄짜리만. 길면 중첩 함수. operator 모듈 우선.

Conditional Expressions

한 줄에 들어가는 간단한 경우만.

Properties

가벼운 계산·검증에만. 비싼 연산/부수효과는 메서드로.

Power Features

메타클래스, 바이트코드 조작, __del__, 리플렉션 해킹 등은 피한다 — 읽고 디버그하기 어렵다.

Main

스크립트도 if __name__ == "__main__": main() — import 시 부수효과 방지.

Getters/Setters

단순 접근은 공개 속성. 의미 있는 로직이 생기면 property로 전환 (호출자 수정 불필요).

Function Length

약 40줄을 넘으면 분리 가능한지 검토.
