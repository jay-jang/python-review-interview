데코레이터: 올바르게 만들기

def timed(func): def wrapper(*args, **kwargs): start = time.time() func(*args, **kwargs) # 반환값 버림! print(func.__name__, time.time() - start) return wrapper # __name__, __doc__ = wrapper import functools, time, logging from collections.abc import Callable def timed[**P, R](func: Callable[P, R]) -> Callable[P, R]: @functools.wraps(func) def wrapper(*args: P.args, **kwargs: P.kwargs) -> R: start = time.perf_counter() try: return func(*args, **kwargs) finally: log.debug("%s took %.4fs", func.__qualname__, time.perf_counter() - start) return wrapper
def retry(times: int = 3, exceptions: tuple[type[Exception], ...] = (Exception,), backoff: float = 0.5): def decorator(func): @functools.wraps(func) def wrapper(*args, **kwargs): for attempt in range(1, times + 1): try: return func(*args, **kwargs) except exceptions: if attempt == times: raise time.sleep(backoff * 2 ** (attempt - 1)) return wrapper return decorator @retry(times=5, exceptions=(httpx.TransportError,)) def fetch(url: str) -> bytes: ...
Expert 리뷰 포인트
• @retry를 비멱등(non-idempotent) 연산(결제, POST)에 붙이면 중복 실행
• async 함수에 동기 데코레이터 → 코루틴 객체만 반환, 시간 측정·재시도 무의미 (inspect.iscoroutinefunction으로 분기)
• 데코레이터는 import 시점에 실행 → 무거운 작업 금지
• 지터(jitter) 없는 지수 백오프는 thundering herd 유발

디스크립터 프로토콜

__get__/__set__/__delete__를 가진 객체를 클래스 속성으로 두면 속성 접근을 가로챕니다. property, classmethod, staticmethod, 함수(→ 바운드 메서드), __slots__ 모두 디스크립터입니다.

class Positive: def __set_name__(self, owner, name): # 3.6+: 속성 이름 자동 전달 self.private = f"_{name}" def __get__(self, obj, objtype=None): if obj is None: # 클래스에서 접근 시 return self return getattr(obj, self.private) def __set__(self, obj, value): if value <= 0: raise ValueError(f"{self.private[1:]} must be > 0") setattr(obj, self.private, value) class Order: qty = Positive() price = Positive() def __init__(self, qty, price): self.qty, self.price = qty, price Order(0, 10) # ValueError: qty must be > 0

속성 조회 우선순위

  1. 데이터 디스크립터 (__set__ 또는 __delete__ 있음, 예: property) — 클래스(MRO)
  2. 인스턴스 __dict__
  3. 논데이터 디스크립터 (__get__만, 예: 함수, cached_property) 및 일반 클래스 속성
  4. __getattr__ (위에서 모두 실패했을 때만)
그래서 cached_property는 논데이터 디스크립터라, 첫 계산 후 인스턴스 __dict__에 값을 넣으면 다음부턴 디스크립터를 거치지 않습니다 — 빠른 이유.
리뷰 기준 디스크립터는 ORM 필드, 검증 프레임워크처럼 같은 패턴이 많은 클래스에 반복될 때 가치가 있습니다. 한두 개 필드라면 property가 더 읽기 쉽습니다.

메타클래스 vs __init_subclass__ vs 클래스 데코레이터

class RegistryMeta(type): registry = {} def __new__(mcs, name, bases, ns): cls = super().__new__(mcs, name, bases, ns) if bases: mcs.registry[ns.get("name", name)] = cls return cls class Plugin(metaclass=RegistryMeta): ... class Plugin: registry: dict[str, type["Plugin"]] = {} def __init_subclass__(cls, /, name: str, **kwargs): super().__init_subclass__(**kwargs) if name in Plugin.registry: raise ValueError(f"duplicate plugin {name}") Plugin.registry[name] = cls class CsvExporter(Plugin, name="csv"): ... class JsonExporter(Plugin, name="json"): ...

메타클래스 충돌 서로 다른 메타클래스를 가진 두 베이스를 다중 상속하면 TypeError: metaclass conflict. 예: ABC + Django Model 등.

MRO와 협력적 다중 상속 (super)

class Base: def __init__(self, **kw): super().__init__(**kw) # object 까지 체인 이어주기 print("Base") class Logged(Base): def __init__(self, *, log_name="app", **kw): super().__init__(**kw) self.log_name = log_name print("Logged") class Cached(Base): def __init__(self, *, cache_size=128, **kw): super().__init__(**kw) self.cache_size = cache_size print("Cached") class Service(Logged, Cached): pass print([c.__name__ for c in Service.__mro__]) # ['Service', 'Logged', 'Cached', 'Base', 'object'] Service(log_name="svc", cache_size=10) # Base → Cached → Logged 순 출력
  • C3 선형화: 자식이 부모보다 먼저, 선언 순서 유지. Cls.__mro__로 확인.
  • super()는 "부모"가 아니라 MRO상 다음 클래스. Logged의 super()는 Service 인스턴스에서는 Cached를 가리킵니다.
  • 협력하려면 모두 super()를 호출하고 **kwargs를 넘겨야 합니다.
class Logged(Base): def __init__(self): Base.__init__(self)
실무 권장 다중 상속은 상태 없는 믹스인 정도로 제한하고, 그 외엔 조합(composition)을 선호.

메모리 모델: 참조 카운팅, GC, __slots__, weakref

  • CPython은 참조 카운팅으로 대부분 즉시 해제 + 세대별 순환 GC로 순환 참조 수거 (3.14: 증분 GC 도입)
  • __del__은 실행 시점이 보장되지 않음 → 리소스 정리는 컨텍스트 매니저나 weakref.finalize
  • PyPy 등 다른 구현은 참조 카운팅이 아님 → "곧 닫히겠지" 가정 금지
class Point: __slots__ = ("x", "y") def __init__(self, x, y): self.x, self.y = x, y p = Point(1, 2) p.z = 3 # AttributeError — 오타 방지 효과도 # 수백만 개 인스턴스에서 메모리 대폭 절감, 속성 접근도 약간 빠름 # @dataclass(slots=True) 로도 가능 (3.10+)
_listeners = [] # 전역 리스트가 객체를 영원히 붙잡음 class Widget: def __init__(self): _listeners.append(self.on_event) # 바운드 메서드 → self 참조 _cache = {} # 상한 없는 캐시 def get(key): if key not in _cache: _cache[key] = load(key) return _cache[key] import weakref _listeners = weakref.WeakSet() # 또는 WeakMethod _cache = weakref.WeakValueDictionary() # 또는 lru_cache(maxsize=...)

진단 도구: tracemalloc(할당 위치 스냅샷 비교), gc.get_referrers, objgraph, memray, sys.getsizeof(얕은 크기만).

GIL은 인터프리터 내부를 보호할 뿐, 여러 바이트코드에 걸친 내 코드의 불변식은 보호하지 않습니다. "GIL 있으니 락 필요 없다"는 리뷰에서 반드시 지적할 오해. free-threading 시대엔 더욱 중요.
