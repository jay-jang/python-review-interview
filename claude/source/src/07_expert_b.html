asyncio 리뷰 포인트 (2) — 태스크 수명, 취소, 동시성 제한

async def main(urls): for u in urls: asyncio.create_task(fetch(u)) # 참조를 버림 → GC 로 사라질 수 있음 # 예외도 조용히 유실 results = await asyncio.gather(*(fetch(u) for u in urls)) # 10만 개 URL 을 동시에 → 소켓 고갈, 상대 서버 DoS async def worker(): try: await job() except Exception: # 3.8+: CancelledError 는 BaseException ... except BaseException: # 취소를 삼키면 종료가 안 됨 pass
async def main(urls: list[str]) -> list[bytes]: sem = asyncio.Semaphore(20) # 동시성 제한 async def bounded(u: str) -> bytes: async with sem: async with asyncio.timeout(10): # 3.11+ return await fetch(u) async with asyncio.TaskGroup() as tg: # 3.11+ 구조적 동시성 tasks = [tg.create_task(bounded(u)) for u in urls] # 하나라도 실패하면 나머지 취소 + ExceptionGroup return [t.result() for t in tasks]
  • fire-and-forget이 필요하면 태스크를 집합에 보관하고 add_done_callback(set.discard)
  • gather(return_exceptions=True)는 예외를 결과 리스트에 섞음 → 반드시 검사
  • CancelledError를 잡았다면 정리 후 다시 raise
  • async 코드에서 공유 상태는 await 지점 사이에서만 원자적 → await를 사이에 둔 read-modify-write는 asyncio.Lock

contextvars, 스레드 로컬, 전역 상태

_local = threading.local() async def handle(req): _local.request_id = req.id # 같은 스레드의 다른 태스크와 섞임 await process() from contextvars import ContextVar request_id: ContextVar[str | None] = ContextVar("request_id", default=None) async def handle(req): token = request_id.set(req.id) try: await process() # 이 태스크와 자식 태스크에만 보임 finally: request_id.reset(token) class RequestIdFilter(logging.Filter): def filter(self, record): record.request_id = request_id.get() return True
왜 중요한가 asyncio는 한 스레드에서 수많은 태스크를 번갈아 실행합니다. 태스크는 생성 시점의 컨텍스트 복사본을 가지므로 ContextVar는 태스크별로 격리됩니다. asyncio.to_thread도 컨텍스트를 전파합니다.
모듈 전역 가변 상태의 문제
• 테스트 간 오염 (순서에 따라 실패)
• 멀티스레드/free-threading에서 경쟁 조건
• 워커 프로세스마다 따로 존재 (gunicorn 등) → "캐시가 안 맞아요" 버그
→ 리뷰 시 "이 상태는 누가 소유하고, 수명은 얼마이며, 동시에 접근하나?"를 질문
