  • 중첩 2단계 이상, 조건이 여러 개면 일반 for 문이나 헬퍼 함수가 낫습니다.
  • 부수효과(출력, append, DB 저장)는 for 문으로.
  • list(map(lambda x: x * 2, xs)) → [x * 2 for x in xs]가 더 읽기 쉽습니다. 이미 있는 함수라면 map(str, xs)는 괜찮습니다.

EAFP vs LBYL

LBYL (Look Before You Leap): 먼저 검사하고 실행.
EAFP (Easier to Ask Forgiveness than Permission): 일단 실행하고 예외 처리. Python 커뮤니티는 대체로 EAFP를 선호합니다.

import os if os.path.exists(path): # 검사 시점 with open(path) as f: # 사용 시점 - 그 사이 삭제되면? data = f.read() try: with open(path, encoding="utf-8") as f: data = f.read() except FileNotFoundError: data = ""
# ❌ try 가 너무 넓어 엉뚱한 KeyError 까지 삼킴 try: user = users[uid] send(user["email"], build_body(user)) except KeyError: user = None # ✅ try: user = users[uid] except KeyError: log.warning("unknown user %s", uid) return send(user["email"], build_body(user))
균형 예외가 "정상 흐름"에서 매우 자주 발생하면(예: 90%가 키 없음) dict.get 같은 LBYL이 더 명확하고 빠를 수 있습니다. 3.11부터 예외가 발생하지 않는 try는 비용이 거의 0 입니다(zero-cost exceptions).

컨텍스트 매니저 (with)

from contextlib import contextmanager, suppress, ExitStack import time @contextmanager def timer(name: str): start = time.perf_counter() try: yield finally: # 예외가 나도 실행되게 finally! log.info("%s took %.3fs", name, time.perf_counter() - start) with timer("load"): load() with suppress(FileNotFoundError): os.remove(tmp) with ExitStack() as stack: # 개수가 동적인 리소스 files = [stack.enter_context(open(p)) for p in paths]
리뷰 포인트 @contextmanager에서 yield를 try/finally로 감싸지 않으면 예외 시 정리 코드가 실행되지 않습니다. __exit__이 True를 반환하면 예외를 삼키므로 주의.

for-else, try-else-finally, walrus

리뷰 기준 walrus는 중복 계산이나 어색한 while True: ... break를 없앨 때 좋지만, 복잡한 조건 안에 숨기면 가독성이 떨어집니다. 우선순위 때문에 (m := f()) is not None처럼 괄호가 필요한 경우가 많습니다.

구조적 패턴 매칭 match (3.10+)

def handle(event: dict) -> str: match event: case {"type": "click", "pos": (x, y)}: return f"click at {x},{y}" case {"type": "key", "key": str(k)} if k.isprintable(): return f"key {k}" case {"type": "scroll", "delta": int() | float() as d}: return f"scroll {d}" case {"type": t}: return f"unknown {t}" case _: raise ValueError(event) @dataclass class Point: x: int y: int match p: case Point(x=0, y=0): ... case Point(x=0, y=y): ... # y 에 캡처 case [first, *others]: ... # 시퀀스 패턴
가장 흔한 실수: 이름은 캡처 패턴 RED = "red" match color: case RED: # 비교가 아니라 'RED' 라는 변수에 캡처! 항상 매칭 ... case "blue": ... # SyntaxError: name capture 'RED' makes remaining patterns unreachable # (뒤에 case 가 없으면 에러 없이 조용히 모든 값에 매칭되고 RED 를 덮어씀) 비교하려면 점이 들어간 이름(Color.RED, consts.RED)을 쓰세요.
  • dict 패턴은 부분 매칭(추가 키 허용), 시퀀스 패턴은 길이까지 매칭
  • str은 시퀀스 패턴에 매칭되지 않음
  • 단순 값 분기 3~4개라면 if/elif나 dict 디스패치가 더 단순할 수 있음 → 구조 분해가 필요할 때 쓰는 것이 리뷰 기준

dataclass, NamedTuple, Enum

선택지쓸 때
dataclass일반적인 데이터 객체. 기본은 가변, frozen으로 불변
typing.NamedTuple튜플 호환(언패킹, 인덱싱)이 필요할 때, 가볍고 불변

리뷰 포인트
• tags: list = [] → dataclass가 ValueError로 막아줌. field(default_factory=list)
• frozen=True여도 내부 리스트는 변경 가능 → tuple 고려
• eq=True이고 frozen=False면 __hash__가 None (set/dict 키 불가)
• 외부 입력은 dataclass만으로 검증되지 않음
